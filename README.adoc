= FPSOT vocabularies specification

Rules for how FPSOT projects publish controlled vocabularies, such as code lists, classifications and thesauri, as W3C SKOS concept schemes.
They cover stable addresses and codes, labels and definitions in English and French, hierarchy and collections, deprecation and versions, mappings to the schemes of other bodies, published files, and binding in LinkML models.
Version 0.1 is a draft.

== Implement this spec

Read the normative text in `spec/en/` or `spec/fr/`.
Start with `index.adoc`, then read the seven parts.
Each requirement has an ID from `VOC-001` to `VOC-065`.
Write each scheme in Turtle, generate its JSON-LD and CSV files, and bind it in your LinkML model with an enum whose values point to the concept URIs.
The script `model/check-scheme.py` checks a scheme against the rules that a tool can test.

== Adopt this spec

Read the guide in `docs/modules/en/pages/index.adoc` or `docs/modules/fr/pages/index.adoc`.
It builds a small scheme of document types, in English and French, and binds it in a LinkML model.
To require the spec, name it in a contract or a policy, and ask that each published vocabulary pass the checks of VOC-054.
The comparison data in `jurisdictions/` shows how the rules of Canada and Québec relate to each requirement.

== Layout

[cols="1,3"]
|===
| Folder | Content

| `spec/`
| Normative text, in English and French. `book.adoc` joins the pages into one book, published as PDF with each release.

| `docs/`
| Guides, in the Antora folder layout.

| `model/`
| The example scheme `document-types.ttl`, its generated JSON-LD and CSV files, its LinkML binding, and valid and invalid examples. Run `model/test-model.sh` after a change.

| `skill/`
| The agent skill: a short summary that cites requirement IDs.

| `rules/`
| Machine-checkable rules. None yet.

| `diagrams/`
| PlantUML sources and their rendered SVG files. None yet.

| `jurisdictions/`
| Comparison data: the international baseline, Canada and Québec.
|===
