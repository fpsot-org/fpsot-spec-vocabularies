= Spécification FPSOT sur les vocabulaires
include::_fpsot-terms.adoc[]

Cette spécification fixe comment les projets de la {abbr-fpsot-first} publient des vocabulaires contrôlés.
Un vocabulaire contrôlé est un ensemble fixe de valeurs dont le sens est convenu, comme des types de documents.
Les listes de codes, les classifications et les thésaurus sont tous des vocabulaires contrôlés.
Chacun est un schéma de concepts du modèle link:https://www.w3.org/TR/skos-reference/[SKOS] du {abbr-w3c-first}.
Deux systèmes qui emploient le même schéma s’entendent alors sur chaque code, ses libellés et son sens.

Les règles comportent sept parties.

* Les xref:identity.adoc[schémas, concepts et codes] : l’adresse et le code de chaque valeur.
* Les xref:labels.adoc[libellés et définitions] : le texte que les personnes lisent, en anglais et en français.
* La xref:hierarchy.adoc[hiérarchie et les collections] : comment ranger et grouper les concepts.
* Le xref:lifecycle.adoc[cycle de vie et les versions] : comment un schéma change sans briser les anciennes données.
* Les xref:mappings.adoc[correspondances] : les liens vers les schémas d’autres organismes.
* La xref:publishing.adoc[publication] : les fichiers de chaque version et leur vérification.
* La xref:binding.adoc[liaison dans les modèles de données] : le lien entre un champ d’un modèle LinkML et un schéma.

== Spécifications liées

Cette spécification s’appuie sur d’autres spécifications de {abbr-fpsot}.
La spécification sur le nommage fixe la forme des adresses et des codes.
La spécification sur l’internationalisation fixe les étiquettes de langue et le repli entre les langues.
La spécification de rédaction fixe comment écrire les libellés et les définitions.
La spécification sur les types de données fixe comment les données conservent une valeur de code et un identifiant.
La façon dont une {abbr-api-first} sert un vocabulaire relève des spécifications de {abbr-fpsot} sur la conception d’{abbr-api}.

== Conformité

[quote, 'link:https://www.rfc-editor.org/info/rfc8174[RFC 8174]']
____
The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "NOT RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in BCP 14 (link:https://www.rfc-editor.org/info/rfc2119[RFC 2119], link:https://www.rfc-editor.org/info/rfc8174[RFC 8174]) when, and only when, they appear in all capitals, as shown here.
____

Les mots clés suivent l’exigence WRT-010 de la spécification de rédaction de {abbr-fpsot}.
La version française emploie les mots clés français de l’exigence WRT-011.

Un schéma est conforme quand chacune de ses versions respecte toutes les règles DOIT qui s’appliquent à un schéma.
Un système est conforme quand il lit et conserve les codes comme l’exigent VOC-033, VOC-037 et VOC-064.
Un modèle de données est conforme quand ses liaisons respectent les règles de la partie sur la liaison.
